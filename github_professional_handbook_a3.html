CH 01

บทนำและการติดตั้งครั้งแรก (Initial Setup & Installation)

เตรียมความพร้อมเครื่องคอมพิวเตอร์และตั้งค่าตัวตนพื้นฐานก่อนเริ่มใช้งาน Git

1.1 ติดตั้ง Git บนเครื่องคอมพิวเตอร์
sudo apt update && sudo apt install git Ubuntu / Debian
brew install git macOS (Homebrew)
1.2 ตั้งค่าบัญชีผู้ใช้ (Identity)
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
1.3 ตรวจสอบการตั้งค่า
git config --list
CH 02

การเริ่มต้นสร้างและเชื่อมต่อ Repository (Repository Initialization & Setup)

คู่มือการตั้งค่าโปรเจกต์และการเชื่อมต่อ Git กับ GitHub ทั้ง 2 วิธีหลัก (ผ่านหน้าเว็บไซต์ และผ่าน Terminal ด้วย GitHub CLI) รวมถึงการโคลนโปรเจกต์เมื่อย้ายเครื่อง

กรณีที่ 1: สร้างบนเว็บไซต์ GitHub ก่อน แล้วเชื่อมต่อจากในเครื่อง

วิธีมาตรฐาน สร้างเรโปบนเว็บเบราว์เซอร์ก่อน แล้วนำลิงก์มาผูกกับโปรเจกต์เดิม

1.1 สร้าง New Repo บนเว็บ (ไม่ต้องติ๊กเลือก README)
1.2 เข้าสู่โฟลเดอร์โปรเจกต์: cd ~/Desktop/Books/"Ebook - Dechatorn"
1.3 เปิดใช้ Git และผูก Remote: git init git remote add origin https://github.com/Dechatorn200x/Ebook---Dechatorn.git
1.4 ดึงข้อมูลตั้งต้น (กรณีมี .gitignore บนเว็บ): git pull origin main --allow-unrelated-histories Note: หาก Editor เด้งให้กด Esc ตามด้วยพิมพ์ :wq แล้ว Enter
1.5 บันทึกและส่งโค้ด: git add . git commit -m "Initial commit ebook files" git push -u origin main
กรณีที่ 2: สร้างและเชื่อมต่อผ่าน Terminal (ด้วย GitHub CLI)

วิธีสะดวกรวดเร็วโดยไม่ต้องสลับไปหน้าเว็บ สร้างเรโปและดันขึ้นคลาวด์ได้ทันที

2.1 เข้าสู่โฟลเดอร์โปรเจกต์: cd ~/Desktop/Books/"Ebook - Dechatorn"
2.2 ล็อกอิน GitHub (ทำครั้งแรกครั้งเดียว): gh auth login
2.3 สร้างเรโปใหม่และ Push ทันที: gh repo create Ebook---Dechatorn --public --source=. --push
กรณีที่ 3: โคลนโปรเจกต์เดิมลงเครื่องใหม่ (Clone Repository)

วิธีดึงโค้ดทั้งหมดลงมาทำงานต่อเมื่อย้ายเครื่องคอมพิวเตอร์ใหม่ โดยใช้บัญชีเดิม

3.1 ย้ายไปโฟลเดอร์ที่ต้องการเก็บงาน: cd ~/Desktop/Projects
3.2 โคลนโปรเจกต์ผ่าน HTTPS หรือ GitHub CLI: git clone https://github.com/Dechatorn200x/Ebook---Dechatorn.git หรือใช้ GH CLI: gh repo clone Dechatorn200x/Ebook---Dechatorn
3.3 เข้าไปในโฟลเดอร์เพื่อเริ่มทำงานต่อ: cd Ebook---Dechatorn
CH 03

วงจรการทำงานประจำวัน (Daily Git Workflow)

ลำดับขั้นตอนพื้นฐานในการเช็คสถานะ บันทึกงาน และส่งขึ้นคลาวด์

ตรวจสอบสถานะและกิ่งปัจจุบันก่อนเริ่มลงมือเขียนโค้ด
git branch
git status
บันทึกและส่งโค้ดขึ้น GitHub เมื่อแก้ไขเสร็จสิ้น
git add .
git commit -m "ข้อความอธิบายการเปลี่ยนแปลง"
git push
CH 04

การจัดการ Branch สำหรับพัฒนาฟีเจอร์ใหม่

เทคนิคการแยกกิ่งงานเพื่อไม่ให้กระทบกับโค้ดหลักบน main และการ Push ขึ้น GitHub ครั้งแรก

สร้างและสลับไปกิ่งใหม่ทันที (กรณีเผลอเขียนบน main สามารถใช้คำสั่งนี้ย้ายโค้ดตามมาได้)
git switch -c ชื่อกิ่งใหม่
ส่งกิ่งใหม่ขึ้น GitHub เป็นครั้งแรก (ผูกลิงก์รีโมท)
git push -u origin ชื่อกิ่งใหม่
CH 05

การลบกิ่ง (Deleting Branches) ทั้งแบบ Local และ Remote

หลังจากรวมกิ่ง (Merge) เข้าสู่ main เรียบร้อยแล้ว ควรลบกิ่งฟีเจอร์ที่ไม่ใช้แล้วทิ้งเพื่อความสะอาดของโปรเจกต์

5.1 ลบกิ่งในเครื่องคอมพิวเตอร์ (Local Branch)
git branch -d ชื่อกิ่ง ลบปกติ (ต้องผ่านการ merge แล้วเท่านั้น)
git branch -D ชื่อกิ่ง บังคับลบ (กรณีไม่ได้ merge แต่ต้องการลบทิ้งทันที)
5.2 ลบกิ่งบนคลาวด์ GitHub (Remote Branch)
git push origin --delete ชื่อกิ่ง
CH 06

การรวมกิ่ง (Merging)

ขั้นตอนการดึงโค้ดล่าสุดจาก main มารวมกับฟีเจอร์ที่เราทำเสร็จแล้ว

สลับมาที่กิ่ง main และอัปเดตโค้ดให้เป็นปัจจุบัน
git checkout main
git pull
ดึงกิ่งฟีเจอร์มารวมเข้ากับ main
git merge ชื่อกิ่งฟีเจอร์
ส่งโค้ดที่รวมแล้วขึ้น GitHub
git push
CH 07

คำสั่งเสริมที่มีประโยชน์และ Pro Tips

เทคนิคและคำสั่งฉุกเฉินในการแก้ไขสถานการณ์เฉพาะหน้า

การยกเลิกการเปลี่ยนแปลงทั้งหมด (Hard Reset & Clean)
git reset --hard HEAD
git clean -fd
ดูประวัติแบบกราฟย่อ
git log --oneline --graph --all
แก้ไขข้อความ Commit ล่าสุด
git commit --amend -m "ข้อความใหม่"
